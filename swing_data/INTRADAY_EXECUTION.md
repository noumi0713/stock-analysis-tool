# 時刻指定成行注文の約定シミュレーター（第6段階）

朝に固定した `picks` と `snapshot`、引け後の5分足SQLiteを読み、200万円の現物買いだけを評価します。買い・売り時刻は09:00〜15:20の5分単位、100株単位、1銘柄100万円・最大3銘柄です。買い後に売った資金は同日中の別注文に再利用しません。

指定した5分足の始値に片道0.05%の価格ずれを加減し、片道0.05%の費用を差し引いた**推定損益**を示します。足の高値で買い、安値で売った場合の保守的な参考値も併記します。どちらも実際の成行約定を証明しません。注文株数がその5分間の出来高の10%を超える場合は、価格への影響を評価できないため未確定とします。

指定時刻の足がない場合、理由を裏付けるイベント情報がなければ次の足へ自動的に飛ばさず未確定とします。特別気配・売買停止の時刻が別途確認された場合は、その終了後の最初の足へ繰り延べて推定します。足と停止情報が矛盾する場合も未確定です。値幅制限の価格が入力され、買いがストップ高または売りがストップ安の価格なら、待ち行列の順番が不明なので約定した扱いにはしません。売りを評価できず建玉が残る場合、当日の最終資産額を出しません。

イベント情報は検証済みの事実を手入力するJSONです。自動収集機能はありません。例:

```json
{
  "trading_date": "2026-09-28",
  "tickers": {
    "9984.T": {
      "limit_up": 12345,
      "limit_down": 9876,
      "untradable": [
        {"start": "09:30", "end": "09:50", "reason": "special_quote"}
      ]
    }
  }
}
```

`reason` は `special_quote`、`halt`、`other` を使用します。`end` は取引不能区間に含めません。証拠のない時刻を推測して入力しないでください。

```bash
python -m swing_data.intraday_execution \
  --picks picks.json --snapshot morning.json --db intraday_5m.sqlite \
  --market-events verified_events.json --output execution.json
```

イベント情報がなければ `--market-events` は省略できます。`ESTIMATED_COMPLETE` は全注文について計算可能という意味で、実約定の確定ではありません。`UNSETTLED` は損益を集計しません。取引所の板・約定履歴・ブローカーの注文履歴がない限り、実際の約定可否は断定できません。結果は勝負台帳に記録します。

GitHub Actions の **Review fixed-time order execution** を手動実行し、取引日を入力すると、朝の保存済みJSONと最新の5分足DBを読み取って同じ判定を行います。必要なら確認済みイベントJSONを入力します。結果は30日保存のArtifactでダウンロードできます。判定不能ならActionは失敗として表示され、理由は出力できた `execution.json` に記録されます。過去の日の価格データが現在のDBに残っていない場合、判定はできません。
