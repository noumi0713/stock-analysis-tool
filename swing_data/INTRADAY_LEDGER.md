# 予想・結果台帳（第7段階）

当日08:15までに保存した予想と朝の入力、引け後の5分足を結び、20取引日のフォワード検証を記録します。`Record forward-test contest outcome` を取引日の15:30 JST以降に手動実行し、日付を指定します。予想や約定を後から作り直して成績に混ぜないため、朝のJSONは `morning-0815-snapshots` ブランチから読み、予想と朝の入力のSHA-256を確認します。対象日のDBに必要な足がなければ `UNSETTLED` として記録します。

出力は `intraday-forward-ledger` ブランチです。`days/YYYY/MM/YYYY-MM-DD/rev-0001.json` に朝の予想全文、元のバイト列、結果、各ハッシュを保存します。既存の日付への再実行は拒否します。未確定日のみ、確認済みの市場イベントJSONと `amend_unsettled=true` を付けて `rev-0002.json` を追記できます。旧版を残し、前の版のハッシュでつなぎます。`summary.json` は最新版から再生成する集計です。Gitの履歴と版の連鎖を確認して監査します。イベントの事実確認は入力者が行います。

集計には記録済み取引日数、欠けている東証取引日、見送り日、推定取引日、未確定日、日次損益を含めます。連続した資産額、勝率、プロフィットファクター、最大ドローダウンは、記録範囲に未確定日・欠落日がないときだけ計算します。損失日がない場合のプロフィットファクターは `null` です。対象は最初の20記録で、21件目以降は勝負の集計から除きます。20日に満たない集計は途中経過です。

**損益は5分足を使った推定値であり、実際のブローカー約定成績ではありません。** 注文板、特別気配、値幅制限、発注結果が未確認なら誤差や未確定が残ります。10日で選ぶ暫定モデルの有効性は、この事前固定した予想と事後結果の比較で検証します。

ローカルでの初回記録例:

```bash
python -m swing_data.intraday_ledger \
  --picks picks.json --snapshot morning.json \
  --db intraday_5m.sqlite --archive forward-ledger
```

未確定日の修正例は、`--market-events verified_events.json --amend-unsettled` を追加します。自動記録や通知は次の段階です。
