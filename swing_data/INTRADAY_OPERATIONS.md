# 初期取得、朝の通知と失敗監視

初期取得の保存ブランチがない間は、04:15 JSTのActionsが59暦日分を取得します。このワークフロー自身をmainに追加・変更した際にも初期取得を試します。既存の5分足DBができた後は、平日16:45 JSTの定期更新で直近7暦日を更新します。YahooがHTTP 429を返す、品質チェックがFAILになるなどの場合はDBを公開しません。`Intraday 5-minute database` の失敗ログとArtifactを確認します。

平日08:05 JSTに朝の入力と予想を凍結し、入力がREADYでハッシュが一致する成功時は銘柄・株数・買い時刻・売り時刻、戦略上の見送り時は理由をGitHub Issueでリポジトリ所有者に通知します。入力不備や処理失敗は「有効な予想が保存されていない」Issueを作ります。08:25 JSTの監視ワークフローは、定期実行が起きなかった場合を含め、有効な予想がなければ同じ日付のIssueで異常を知らせます。同日Issueの重複は抑止します。

GitHub Actionsのスケジュール開始時刻とGitHub Issue通知の到達時刻には遅延があり得ます。08:15ちょうどのスマホ配信は保証しません。GitHubの通知設定で、当リポジトリからのIssue担当通知を受け取る設定が必要です。**08:15までに朝の予想が保存されていない日は、遅れて出た候補で取引せず見送ります。**

初回は `intraday-5m-data` ブランチの品質レポートがPASSで、直近10取引日の足が対象銘柄に揃っていること、続いて `morning-0815-snapshots` に当日の予想が期限前に保存されていることを確認してください。保存前の日の勝負結果を事後作成しません。
