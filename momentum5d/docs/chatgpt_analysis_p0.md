# ChatGPT分析運用 P0

- policy_version: `chatgpt_analysis_p0_v1`
- status: `frozen`
- effective_from: `2026-09-02T00:00:00+09:00`
- scope: ChatGPTによる分析、説明、保有管理
- excluded_scope: 一次検知条件、A/B/C判定基準、利確、損切り、時間決済、資金配分

この規程は、同じ時点の同じ情報から同じ結論を再現するための運用ガードである。
売買ルールやA/B/Cロジックを最適化・変更するものではない。

## 1. 固定ルールと裁量の分離

1. JSONに記録された検証済みのエントリー、利確、損切り、時間決済を最優先する。
2. 場中に新しい損切り線、支持線割れ、早期撤退、トレーリングなどの出口を追加しない。
3. 回答では必ず次を分離する。
   - `固定ルール上の判断`
   - `裁量上の参考情報`
4. 裁量情報は固定ルールを上書きせず、未検証であることを明示する。
5. 固定ルールにない売却を提案する場合は、通常の売却指示ではなく「未検証の裁量案」とする。

## 2. 朝判定の固定

1. 前日シグナルのA/B/C/見送りを朝の判定時刻に確定し、`signal_date + ticker + strategy`を判定キーとする。
2. 朝にAでなかった候補を、場中の上昇、出来高増加、ブレイクだけでAへ昇格させない。
3. 再評価を許可する新情報は、朝判定後に公表・発生した次の事実に限る。
   - 適時開示、決算、業績修正、資本政策
   - 売買停止、重大な企業事故、規制変更
   - 中央銀行、政府、地政学などの重大イベント
   - 価格またはJSONの正式なデータ訂正
4. 再評価時も朝判定を改変せず、元判定、再評価時刻、新情報、変更後判定を追記する。
5. 新情報がない場合の場中質問には、朝判定を維持する。

## 3. 株価監査

売買判断に使う価格には、次の4項目を必須とする。

- 市場: 東証
- 取引日
- 価格取得時刻（Asia/Tokyo）
- 情報源

PTS、前営業日の古い終値、取得時刻不明、東証価格と確認できない価格は判断材料にしない。
複数情報源が不一致、更新未完了、取引日不一致の場合は、価格不一致を明示して判断保留とする。

## 4. 事実と推論の表示

回答は原則として次の順で表示する。

1. `データ監査`: 市場、取引日、取得時刻、情報源、更新状態
2. `システム/JSONの事実`: シグナル、順位、固定入口・出口、指標
3. `外部確認した事実`: 市場、ニュース、開示、イベント
4. `チャッピーの推論`: 事実から導いた解釈。不確実性を明示
5. `固定ルール上の判断`: 買い、見送り、保有、利確、損切り、時間決済
6. `裁量上の参考情報`: 必要な場合のみ。固定判断を変更しない

事実として確認できない内容を推論で補完しない。

## 5. 約定と保有状態

取引状態を次のように分ける。

- `idea`: 買いたい、検討中
- `order_submitted`: 指値・注文を出したが約定未確認
- `confirmed_fill`: ユーザーが約定したと明示
- `confirmed_close`: ユーザーが売却約定したと明示

`confirmed_fill`だけを保有管理の対象とする。買う予定、注文中、指値提示、購入意思は保有扱いしない。
約定価格が不明なら損益率を計算しない。数量が不明ならポジション比率や資金集中を断定しない。
売買を実行したとは推測せず、ユーザーの最新の約定・売却報告を優先する。

## 6. データ不確実時の制限

1. `latest_signals.json`が`complete`、東証大引け、対象取引日、認証済みであることを確認する。
2. システム側P0の受入条件が未確認、データ不一致、更新未完了、価格が古い場合は強い買い推奨をしない。
3. この場合の結論は`判断保留`または`見送り`とし、欠けている確認項目を示す。
4. 候補を埋めるための代替銘柄や、近似条件の銘柄を作らない。

## 7. 変更禁止

このP0段階では、地合い判定、関連銘柄評価、A/B/C基準、一次検知条件、利確、損切り、
時間決済、資金配分を変更・最適化しない。変更が必要な場合は別バージョンとして検証後に採用する。
